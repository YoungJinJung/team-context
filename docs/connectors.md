# 커넥터 개발 안내

Team Context는 업무 도구별 데이터를 공통 형태로 연결하려는 로컬 프로토타입입니다. 이 문서는 **현재 코드의 계약**을 설명합니다. AWS 배포와 비공개 자료를 위한 운영용 권한 모델은 아직 없습니다. 전체 흐름은 [아키텍처 문서](architecture.md)를 확인하세요.

## 현재 연결 범위

| 공급자 | 현재 동작 | 아직 없는 기능 |
| --- | --- | --- |
| GitHub.com | 공개 PR 수집·검색, GitHub App 사용자 OAuth와 비공개 PR 미리보기 | 비공개 PR 저장·검색, 소스 파일 수집, GitHub Enterprise |
| GitLab.com | 공개 MR 수집·검색, OAuth PKCE, 비공개 MR 로컬 수집·권한 재확인 검색 | 소스 파일 수집, 자체 호스팅, 자동 권한·삭제 전파 |
| Linear | OAuth PKCE, 팀·이슈 미리보기 | 이슈 저장·동기화 |
| Microsoft Teams | Entra OAuth PKCE, 팀·채널 첫 페이지 미리보기 | 채팅·메시지 수집, 전체 페이지 조회 |
| Jira · Confluence | 없음 | OAuth 연결 및 문서·티켓 수집 |

미리보기는 브라우저 응답으로만 제공하며 공용 검색에 저장하지 않습니다. GitLab 비공개 MR 스냅샷은 별도 로컬 S3 키에 저장됩니다. 현재 LocalStack은 실제 조직 토큰이나 비공개 자료를 안전하게 보호하는 운영용 저장소가 아닙니다.

## 공개 소스 커넥터 계약

`connectors/` 안의 Python 모듈은 서버 시작 시 `app.discover()`가 탐색합니다. 서버를 다시 시작해야 새 모듈이 반영됩니다. 예제는 [GitHub](../connectors/github.py)와 [GitLab](../connectors/gitlab.py) 커넥터입니다.

- `MANIFEST`: 고유한 `id`, 표시용 `name`, `category`, 입력 폼용 `fields`를 포함합니다.
- `connection_id(config)`: 입력을 검증하고 `github:owner/repo`처럼 안정적인 소스 ID를 반환합니다. 토큰이나 비밀을 포함하지 않습니다.
- `collect(config)`: `id`, `visibility`, `type`, `title`, `url`, `updated_at`, `body`를 가진 레코드 목록을 반환합니다. 현재 공용 수집과 검색은 `visibility: public`을 전제로 합니다.

레코드 ID는 공급자와 소스 범위를 포함해야 합니다. 페이지 상한, 중복 ID, API 실패를 처리하고 일부만 수집한 결과를 전체 성공으로 반환하지 않아야 합니다. 공급자가 응답한 URL을 무조건 신뢰하지 말고, 허용한 호스트와 경로 및 리디렉션 처리 방식을 검증하세요. 새 공급자를 공개 검색에 추가하려면 [원본 재검증](../source_verification.py), UI 링크 허용 범위 및 관련 테스트도 함께 확장해야 합니다. `connectors/`의 코드는 애플리케이션 프로세스에서 실행되므로 신뢰할 수 있는 커넥터만 설치하세요.

## 인증과 비공개 자료

기존 OAuth 구현은 `auth/`와 서버 라우트에 공급자별로 연결되어 있습니다. 위의 공개 커넥터 계약만 구현한다고 OAuth 연결이 자동으로 추가되지는 않습니다. 이 제한을 해소하는 작업은 [#53](https://github.com/YoungJinJung/team-context/issues/53)입니다.

사용자는 개인 액세스 토큰을 직접 입력하지 않습니다. GitLab.com과 Linear, Teams는 OAuth PKCE를 사용하고, GitHub는 GitHub App 사용자 인증을 사용합니다. GitHub App에는 별도의 **앱 클라이언트 비밀**이 필요하며, 이는 사용자의 개인 토큰과 다릅니다. 현재 데모는 공급자별 브라우저 쿠키와 세션 참조를 분리하고, 참조는 로컬 DynamoDB에 해시해 보관하며 토큰은 로컬 Secrets Manager에 저장합니다. 공급자 자격증명을 임의 호스트 또는 리디렉션 대상으로 전달하지 않습니다.

새로운 비공개 커넥터는 수집자의 권한만 확인해서는 안 됩니다. 조회 요청자의 공급자 권한과 원본 내용·버전을 확인하고, 실패나 미확인 상태에서 저장된 내용을 반환하지 않아야 합니다. 공개·비공개 키 공간, 원본 삭제·권한 변경, 테넌트 격리, 감사와 비밀 보관도 설계 범위입니다. 현재 GitLab 경로의 제한과 운영 전 과제는 [아키텍처 문서](architecture.md#현재-구현-현황)에 설명합니다.

## 테스트와 기여

입력 검증, 페이지 경계, 중복, 오류, 재시도, 원본 권한 회수, 데이터 격리와 원본 변경을 중심으로 테스트를 추가하세요. 로컬 에뮬레이터에는 생성한 가짜 데이터만 사용하고 테스트 후 정리합니다. 전체 테스트와 백엔드 변이 검사 명령은 [개발 안내](development.md#테스트)를 따릅니다. 실제 외부 서비스 검증이 없다면 PR에서 그 한계를 명시하세요.
